# 复核一笔跨夜差价

选跨夜争议样例，在「首免与升级价」选 B-01 的 11/30 23:40。三个杆侧检测并成 45 分钟，50 分钟原记录中去除 5 分钟重叠。原预约在实际到达时有效。

- 23:40–23:50 首免，23:50–24:00 基础价 10 分钟，共 ¥2.00。
- 次日 00:00–00:15 基础价 15 分钟，共 ¥3.00；00:15–00:20 升级价 5 分钟，共 ¥2.00。
- 00:20–00:25 有占位争议，计 ¥0.00。实收回执 0007 为 ¥8.50，与应收 ¥7.00 相差 ¥1.50。

证据附件包含 `evidence` 和留档的 `manifest`。校验时用 UTF-8 JSON 序列化，递归排序字典键，保留中文，逗号及冒号不留空白。对 `evidence` 算 SHA-256，应等于 `manifest.evidence_sha256`。对 `{manifest,evidence}` 算相同摘要，应等于根对象的 `sha256`。

`pricing.stays` 保留停靠源行、到达时预约和相同费率连续段，`settlement.lines` 列出回执来源与差价，`occupancy.disputes` 定位争议分钟。可用原件 SHA-256 对照来源。明文车牌和识别密钥留在各自的输入系统和工作台数据库中。

## 复核杆侧补扫后的认回

杆侧晚到的补扫把到达分钟提前时，原批次挂上的回执会脱离逐单成为游离款。用原清算批次补扫重算，提交时带 `{"parent": "<原留档编号>"}`：

```sh
curl -s localhost:18471/api/dockets -H 'Content-Type: application/json' \
  -d '{"bundle": {...四份原件...}, "parent": "<原留档编号>"}'
```

新批次留档的 `manifest.parent` 指向原批次，`manifest.reclaimed` 列出认回的回执，`manifest.disputed` 列出仍有争议的款。逐单页「补扫认回」表给出每笔认回的原停靠、补扫后停靠、到达分钟与归属依据；「仍有争议的款」列出不能认回的回执及原因。理赔页在原批次链接下重复同样的两张清单。

认回只看原批次自己的归属，不靠放宽时间猜：

1. 该回执在原批次里挂在某笔逐单上；
2. 补扫后停靠覆盖回执的到达分钟，且原停靠的检测编号仍在新停靠里（同一笔停靠向前延伸）；
3. 同车同泊位只有一笔新停靠满足上述条件。

回执的到达分钟、泊位、车辆、金额必须与原批次一致。任一条不成立——到达不在任何新停靠内、原检测编号不再同组、同车同泊位多笔停靠、原批次没有这笔归属——都保留为仍有争议的款，不并入任何逐单。

同一输入和原批次重跑生成同一个留档编号，返回原快照，不重复计收也不重复留档。原批次与补扫批次的证据附件都能各自签发和核验，正文互相链接。`settlement.money.reclaimed_cents` 汇总已认回金额，`orphan_cents` 只统计仍有争议的款。
